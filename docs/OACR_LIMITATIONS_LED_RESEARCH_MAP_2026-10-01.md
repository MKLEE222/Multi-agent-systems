# 从组件和算子出发，用近邻边界检验候选载体

日期：2026-10-01。状态：研究选题与文献筛查记录；不是新主线通过验收，也不是投稿版本。

## 决策变化

母问题是：有限资源下，怎样维护表示对后续操作的充分性？从 OACR 自己的组件、原生更新、表示变换和来源接口触发，先定义操作诱发的区分需求与可执行维护程序，再选择载体。具体数学与接口见 [算子出发的基础规格](OACR_OPERATOR_FIRST_FOUNDATION_2026-10-01.md)。

旧定理、GRACE 实现和已投入的工作不决定新方法；已有底层对象也不因“自己的”而获得新颖性。旧证据保留，未执行的扩大半径轮次暂停。原 T2/T5 门槛和 512 单位封存评估不变；新候选需要自己的贡献、基线和数据契约。

近邻作者明确承认的限制用于发现遗漏的机制和实际需求；跨领域及后续工作用于检验既有解决办法。研究顺序是：底层组件/算子 → 数学规格 → 独立于方法的现象及机制预测 → 候选载体中的原生干预 → 需求证书与维护构造 → 同输入、同资源的强基线检验。作者写了 future work 是线索，不是新颖性证书。现象贡献及已有覆盖见 [现象与机制协议](OACR_PHENOMENON_AND_MECHANISM_PROTOCOL_2026-10-01.md)。

## 同一母问题的三个候选载体

共同研究对象是允许来源和资源约束下的维护程序：识别操作激活的组件需求，选择保留、补取或修复，再由固定原生解释器执行。三者的观察、误差类型和组件结构分别声明；共享问题尚不等于共享一个已验证的方法。

### A：编辑缓存——优先做廉价的算子机制筛查

具体问题：在不使用反向传播、不给优化器额外完整模型副本的条件下，能否控制缓存造成的有限差分偏差，并改善真实编辑质量与完整前向成本的权衡？

候选机制是用少量成对的 fresh/cached 训练损失测量误差，然后决定继续复用、精确刷新受影响部分，或使用偏差校正。不是以缓存下的 loss 下降作为真实成功标准。所有探测、缓存元数据、激活存储和校正调用都计费。

这个机制还没有被选为论文方法。首先必须判定实际依赖关系：若编辑只注入某个 token，而缓存严格位于它之前，确定性的因果模型可以精确复用；此时无须学习刷新策略。不能把“参数/编辑向量变化”直接当作全部缓存失效的证据。

强基线至少包括：每次完整 fresh 双侧前向；精确因果依赖复用；MobiEdit 的原刷新规则；同成本固定频率和随机刷新；常规 multi-fidelity 校正；适用时的 CacheReforge 适配。QZO、AGZO、ZO-Act、AIM-ZO 用于检查优化器改进能否独立解释收益，不机械地混成同一算子。

潜在贡献须是实际可用的误差控制/计算分配机制及其独立任务收益。有限差分误差的三角不等式、缓存可能过时和旧 OACR 等价关系都不作为新理论。

**已执行后的路线变化：** [原生缓存机制探索](OACR_CACHE_RESPONSE_MECHANISM_EXPLORATION_2026-10-01.md)支持覆盖编辑位点的冻结前缀切断后缀损失响应；精确因果边界修正消除结构性问题，预训练数值差异由 fresh 的矩阵分块复现。当前没有学习刷新必要性或精确复用后资源障碍的证据，暂停该固定输入、定权重、单 token 场景的方法主张。A 保留为机制筛查，不能凭重复这个反例升级论文。若继续 A，先核对完整入口和真实改变依赖的操作，再测标准失效/精确重算的全成本。

### B：并发共享记忆——检验来源与提交算子的交互

具体问题：一个共享记忆系统正在生成压缩结果时，源记录被纠正或权限撤销。怎样保证提交的结果仍基于当前合法来源，同时尽量保留未受影响内容，减少重生成和重检索？

先实现标准数据库办法：读版本/权限 epoch、提交校验、失败重试，以及来源依赖的失效闭包。它们是强基线。若这些方法已以低成本解决问题，就结束该候选；不能把加版本号重新包装为新算法。

只有在真实的 LLM 合并、跨源推导或长依赖链中出现可重复的维护成本障碍，才研究更细的声明级依赖验证和局部重生成。数据应来自可公开重放的工具任务或长期工作流；不能只用“撤销一个事实”的单步模板。MAP-Graph、Collaborative Memory 与事件日志重放都应纳入比较。

### C：有限在线码本——检验回收、重绑定后的语义维护

具体问题：新词持续出现，保留槽位不是无限资源。自动绑定、回收、重绑定怎样影响新请求、历史上下文和未干预召回？

先比较传统倒排索引、明确版本化的绑定表、固定保留槽位及常规在线缓存分配。只有出现这些办法无法便宜解决的语义路由问题，才考虑新的在线编码/学习策略。工业流量和公开复现的可得性是首要可行性门槛；本文献线索不授权声称可以复现 OneRetrieval 的线上结果。

## 接下来如何形成可投稿的工作

1. 从公共接口出发，为 A、B 写组件清单、算子读写集合、来源接口及成本表，分别冻结观察契约、允许输入和最强简单基线。A 先做机制筛查；不要求沿用旧图算法或旧数据。
2. 先用固定原生表示和共同操作面板观察现象，检验预先声明的机制干预和消失边界，再加入新修复方法测全成本。只报告完整请求分母，保留失败和无法运行的状态。
3. 一个载体进入主线须有具体、可重复且边界清楚的现象，核对其机制是否已被近邻完整解释；若提出新方法，还须检验尚未由强基线解决的实际障碍与独立收益。先确立一个核心机制，再检查第二载体能否迁移同一预测/证书规则；若核心规则需要重写，则收窄论文范围。
4. 在开发成本与效应大小可估计后，预先确定确认性样本、分组单位、主要对比和停止条件。旧 512 单位评估不充当新问题的便利测试集。
5. 方法与独立证据成立后再按真实贡献选 AI 方法/系统或数据系统方向的投稿渠道。当前不继承旧 JLAMP 路线，也不保证某会某刊录用。

本记录包含近邻地图、底层接口及 A 的局部原生执行结果。A 的固定输入学习型刷新主张暂停，B/C 尚未执行，没有宣布三者具备新颖性或性能优势。下一项义务是检验标准精确维护之后是否仍有实际成本障碍；未证明这个障碍之前不设计新控制器。
