# OCAR/OACR：母问题与共同竞技的执行记录

日期：2026-10-01。结论：成熟主动取证方法已在同输入条件下参赛；当前开发样例
没有显示独有的取证优势。结构编译避免显式枚举隐藏状态，值得继续检验，但简单
结构基线已经达到相同查询数，计算、理论新颖性和真实任务优势尚未建立。

本记录沿用[唯一升级验收](OACR_FINAL_UPGRADE_ACCEPTANCE_GATE_2026-09-30.md)，
不创建新 gate。直接谱系仍为 BRFP → OCAR/OACR；SQEC/EEQ 是同源参照。
用户报告的 EEQ 发表困难与其已取得的基线收益分别保留；没有审稿意见，不能推断
实际拒稿原因。这里落实的研究判断是：自己的问题应产生独立解释，也应在共享任务、
原生评分和同等资源下接受现有方法的竞争。

## 1. 母问题落实到可共同求解的对象

母问题候选：**原生操作改变信息的有效支持以后，如何仅凭当前合法可得的信息，
以可承担的保留、补取和重算成本，继续支持原来的任务行为？**

底层仍从 BRFP 的效应、状态、实体、授权与局部操作出发。上层区分两个义务：
一是当前信息能否决定目标行为；二是程序能否输出实际表示并继续执行原生操作。
定义相容状态集 \(\mathcal V(r,\tau)\)，其中 \(r\) 是旧表示，\(\tau\) 是合法来源回答。
在当前精确结构类，停止取证的条件为

\[
\left|\{B_{C'}(x):x\in\mathcal V(r,\tau)\}\right|=1.
\]

这项条件本身就是已有 equivalence class determination（ECD）问题，不能以 OACR
命名重新计为贡献。共同目标还要求实际输出 \(m\) 满足

\[
\operatorname{Obs}(T_\sigma\operatorname{Dec}(m))
=\operatorname{Obs}(T_\sigma x),\qquad \sigma\in C',
\]

并在动作消费后维护剩余契约，而非每次重置预算。任何参赛方法都可使用同一个合法
编码器和更新器。未来行为可由公开语义合法模拟；隐藏真实状态和验证器结果不可读取。

外部任务的主评价直接采用其官方成败；原生精确性只在其确实适用的载体上另行验证。
在同样任务质量下比较存储、来源访问、模型调用与计算；在同样预算下比较任务质量。
先报告这些量及 Pareto 关系，不用任意合成权重造出“总成本胜利”。

## 2. 已执行的共同竞技

协议：[common_arena_v1.json](../experiments/oacr_theory/common_arena_v1.json)。
实现：[common_arena_v1.py](../experiments/oacr_theory/common_arena_v1.py)。
结果：[OACR_COMMON_ARENA_RESULT_2026-10-01.json](OACR_COMMON_ARENA_RESULT_2026-10-01.json)。
逐请求记录：[压缩 ledger](OACR_COMMON_ARENA_RESULT_2026-10-01.cases.json.gz)。

共同任务是从旧压缩表示与 membership 来源，恢复允许的未来 base-edge failures
下的完整 reachability 行为，输出可维护的持久边集合。公开 DAG、候选集、旧/新
契约、旧表示、来源快照、权限、单位查询成本、均匀旧 source-fiber 先验全部相同。
采用既有 5 个公开过的开发 fixture，共 138 个世界、16 个旧 fiber；不称独立确认。

| 方法 | 来源查询 | cut 请求 / 冷 miss | 模型枚举状态 | 模型阶段原生模拟 |
|---|---:|---:|---:|---:|
| EC² 原目标的确定性均匀特例 | 460 | 324 / 324 | 4,816 | 24,040 |
| EffECXtive 原目标的行为类后验特例 | 460 | 324 / 324 | 4,816 | 24,040 |
| 类信息增益 | 460 | 324 / 324 | 4,816 | 24,040 |
| 精确最优期望查询 DP | 460 | 324 / 324 | 4,816 | 24,040 |
| 所有未保存来源事实补取后重建 | 598 | 393 / 393 | 0 | 0 |
| 结构需求 + 字典序 | 568 | 2,192 / 1,465 | 0 | 0 |
| 结构需求 + 逆字典序 | 536 | 2,148 / 1,435 | 0 | 0 |
| 结构需求 + 短跨度优先 | 460 | 2,074 / 1,379 | 0 | 0 |
| 结构需求 + 本轮一步收益候选 | 464 | 6,964 / 4,264 | 0 | 0 |

以上是 138 个请求的合计，不同计算操作不能直接相加比较。精确 DP 另有 49,846 个
状态与 93,142 次候选评分；三个成熟贪心方法各有 1,612 次在线评分。所有方法在
全部世界输出同一个正确的物理表示，总计保留 320 条边记录，存储收益没有方法差异。
EC²、EffECXtive、类信息增益、短跨度优先的逐世界查询数均与本次最优 DP 策略相同；
一步候选在 4 个世界各多查一次。总数和预算完成曲线均保留，无结果后调参。

EC² 按原先验的跨类边权计算期望 cut，不能把每个回答分支的边权重新归一化。
实现采用论文的快速类计数公式，验证器逐条枚举跨类边，2,370 项评分检查全部一致。
EffECXtive 使用目标行为类后验平方和的期望增益：将目标行为类作为潜在目标，
源世界作为决定观测的细分状态。这是确定性、全部测试可识别目标类的特例，未测噪声。
两者均通过自身 BFS 模拟构建模型，不读取 bitset 原生验证结果。

所有方法的共同编码器只接收旧表示与查询得到的肯定事实。不把 OACR 编码器的收益
只记给自己的方法，不限制成熟方法枚举、模拟、缓存或采用结构优化的合法能力。
本次协议固定为每请求冷启动，缓存清空后才计时；生产系统可摊销模型预处理，下一轮
须同时比较冷启动与复用条件。显式模型枚举是本次实现选择，不是 EC²/EffECXtive
必然需要的代价；尤其 EffECXtive 原文正是为了避免巨大等价类的显式处理。

本地累计 producer 时间仅为单次实现诊断：EC² 约 0.160 秒、EffECXtive 0.167 秒、
信息增益 0.150 秒、DP 0.833 秒、短跨度 0.012 秒、一步候选 0.039 秒。没有重复
测量、来源网络延迟、物理 RSS、存储收费和真实并发，因此不据此宣称总体速度优势。
序列化模型/策略字节也只代表所声明的对象，不是进程内存峰值。

## 3. 这轮排除了什么，下一步检验什么

1. **当前自适应取证增益不能独立承担强论文。** 相对 static-demand 的既有正结果
   保留，但 EC² 等成熟方法已经达到本次精确最优值；新增一步选择器被简单结构顺序
   压过。本次不把它继续当作主算法贡献，也不通过削弱竞争者保住优势。
2. **反循环内核是有效性约束。** 从公开算子、可得输入推导需求，确保预测先于
   隐藏验证结果；它没有自动产生新的主动学习算法。语义商、标准划分细化、
   conditional cut/TR 与 ECD 中已有的部分要明确归属。
3. **结构化计算是可检验的机会。** 已有需求条件
   \(\forall e\in U,\lambda_{G\cup P,A}(e)>h\) 不枚举源世界或未来 failure subsets。
   这里 \(P\) 为已知肯定边，\(U\) 为未知候选，\(\lambda\) 只允许删除指定 base
   边，其余边不可删除。需查清支持依赖偏序是否给出无需先验的查询证书及可证明的
   复杂度边界；短跨度的平局提示基本结构规则可能已经足够。现有数值不证明任何
   一般最优性或与已有算法的分离。
4. **现象必须预测普通任务中的收益与失效。** 候选机制是：支持失效会让先前省略的
   信息变成必需，取得其他支持又可能使它免于补取。先在可观察的 native 更新、实体
   绑定和授权事件上预测哪些保留/补取会改变后续结果，再用原生 evaluator 检验。
   一般依赖失效已有覆盖；若经典维护完整解释并解决该机制，按实际增量收窄贡献。

## 4. 外部竞技的落点与执行顺序

优先接回 BRFP 的工具操作接口，先冻结一个 benchmark revision 和 adapter，不再
只扩大小图枚举。以下是已核对官方语义后的路线选择，尚未完成外部运行。

| 落点 | 保持原生评价 | 与母问题的连接及边界 |
|---|---|---|
| BFCL V3 multi-turn / multi-step | 每轮官方状态与 response 检查，整条任务通过率 | 直接检验状态读写和连续工具操作。维护支持是否影响后续成功是机制分析；不另造 OACR 成败标准 |
| BFCL V4 Memory | 官方 follow-up 回答正确性及必要的显式 memory 查询 | 提供 snapshot/reload 与现成 KV、vector、recursive-summary 后端；可检验跨会话保留与检索。其标准评估从同一最终快照分别提问，单独不能证明连续 WRITE 残余维护 |
| τ 系列工具任务 | 固定对应版本的官方任务奖励与多次运行一致性 | 直接连接用户交互、工具状态与域策略。BRFP 的旧 τ 结果按原版本保留；新的实验需另行固定修订，当前旧仓库已提示任务未更新，不混合新旧分母 |

先做无模型费用的接口检查：producer 能否只接收允许的历史/存储/实时工具响应，
结果能否交给未经修改的官方 evaluator，来源 snapshot 与持久表示如何随 native
操作更新。官方目标/未来答案只进入评价端。适配不成立就返回接口问题，不运行
没有真实表示干预的排行榜比较。

之后在同一个 agent/model、任务集、工具权限与总资源条件下比较：完整保留/重建，
标准依赖维护，已实现的成熟取证策略，以及对应任务原有记忆/摘要后端。EC² 不被
强行当作端到端 agent：它参赛于共同的取证子问题，其他组件相同；端到端方法在
共同官方任务上参赛。机制对照在单独开发集固定，主结果仍是共同官方任务成败。
保存全部来源读写、表示字节、重算、模型 tokens/调用、时延和初始化摊销。

BFCL/τ 的具体公开修订、独立开发/确认拆分以及 adapter 仍待实现；当前 138 个
图世界不替代这些证据。旧 512 单位评估继续封存。本轮完成成熟方法同台执行与
路线约束，不宣称 T2/T5、自然维护证据或发表强度已通过。
