# OACR：从组件和算子推导研究问题

日期：2026-10-01。状态：底层接口、数学规格与候选贡献；尚无新的算法验收或模型结果。

## 1. 研究起点

母问题是：**有限资源下，怎样维护表示对后续操作的充分性？**

向下落实为一个可研究的问题：**操作会激活哪些被省略的信息，能否从组件及其交互结构计算这些需求，并编译成有预算的保留、补取和局部修复程序？**

先定义自己的研究对象、允许输入、原生算子和维护目标，再选择载体、检查近邻。近邻的 limitations/future work 用于发现漏掉的机制和检验贡献边界。本文不要求沿用旧图算法或 GRACE，也不把基础数学换一个名字当作新理论。

## 2. 底层组件与算子接口

组件是能由载体识别、保留、替换或删除的实际单元。它可以是边及来源记录、缓存块、记忆声明及来源、码本绑定；粒度由具体实现固定。组件身份本身也需要存储，不能假定删除内容后仍免费保留其身份。

| 接口 | 输入与输出 | 必须显式给出的条件 |
|---|---|---|
| 原生观察 `Obs` | 实际载体状态 → 输出、合法性或执行轨迹 | 当前答案、权限和任务损失分别定义 |
| 原生操作 `Apply_a` | 实际载体状态、动作 → 输出与后继状态 | 固定解释器；动作含删除、编辑、撤销、重绑定等具体语义 |
| 表示变换 `Encode/Decode` | 可见状态 → 可执行表示；表示 → 原生状态 | 声明可实现的表示族；解码需要的共享状态与来源不免费 |
| 省略 `Drop_K` | 表示、组件集合 K → 可执行表示 | 不能只在审计标签上删除，必须改变原生使用的对象 |
| 补取 `Acquire_Q` | 来源接口、请求 Q → 状态相关证据 W | 权限、版本、存储、通信与获取成本；可能失败 |
| 局部修复 `Repair_S` | 表示、允许证据、区域 S → 可执行表示 | 具体重算或重生成程序；不能直接输出评估答案 |
| 契约更新 `Residual_a` | 当前契约、合法动作 → 剩余契约 | 剩余动作、时域、版本和权限；执行一次不重置时域 |

`Repair_S` 可以由补取、替换、删除和重算组成。没有可执行构造时，它只是待实现接口。证书是由允许输入计算的检查结果，不是一个免费获得的“正确”标签。

现有实现提供了可对照的起点：

- `contract_budget_audit_v1.py` 的 `compile_rep/step_rep` 读取状态相关 delta 证据及剩余 `G,A,h`，保留或省略 delta，再执行消费预算的更新。
- `multi_delta_budget_audit_v1.py` 的 `compile_multi` 在其他持久 additions 存在的条件下判定组件需求，避免把组件交互误写成独立判断。
- 核心可修复性审计明确要求 `W(x)`；只有公共候选宇宙不能识别已经丢失的状态身份。

这些实现是本规格的来源和特殊实例。其既有正确性、范围和未通过的新颖性门槛不因本次重写而改变。

## 3. 上层表达一：操作诱发的区分需求

先取有限、确定性的状态域 X，包含声明的合法历史可到达的状态。参考状态 x 是审计者定义的完整状态，部署中的维护器不因此得到 x。原生动作是 T_a，观察是 q。契约 C 给出前缀封闭的允许动作历史 L(C)、观察规则和时域；空历史也纳入。记

\[
 B_C(x)=\bigl(q(T_\alpha x)\bigr)_{\alpha\in L(C)},
 \qquad T_{\varnothing}x=x.
\]

这是精确行为规格，不是部署时要求枚举的算法。原生操作产生的输出可纳入轨迹状态。若合法性依赖状态，统一动作索引并显式记录非法动作及其后果，不能通过删除非法样本制造等价。

剩余契约 C/a 包含动作 a 后仍允许的历史：

\[
 L(C/a)=\{\beta:a\beta\in L(C)\}.
\]

观察及合法性上下文也随之更新。有限 H 步执行后通常只剩 H-1 步；契约扩展另作一次显式事件处理。

令 E:X\to Z 是当前表示，定义动作所要求的后继行为

\[
 Q_{a,C}(x)=B_{C/a}(T_a x).
\]

一个被当前表示合并、却被动作激活的区分是

\[
 E(x)=E(y),\qquad Q_{a,C}(x)\ne Q_{a,C}(y).
\]

需要研究的具体对象不是“两个隐藏状态不同”，而是这样的区分是否能从部署时允许获得的组件、证据与算子结构中发现和维护。

这里的行为等价、残余契约和因子分解是基础数学。上述定义整理了我们的研究对象，尚未提供新的高效算法。

## 4. 上层表达二：来源可得性决定能否修复

维护器在动作前实际可见的信息记为

\[
 I(x)=(E(x),W(x),m,C,a),
\]

其中 m 是公开元数据，W(x) 是已保留或经授权补取的状态相关来源；获取 W 的过程另行计费。若 x,y 给出相同 I，却有不同的 Q，就不存在仅凭 I 正确恢复目标行为的确定性构造。

在有限、任意标签编码的范围内，必要且充分条件是

\[
 \exists g:\ Q_{a,C}=g\circ I
 \quad\Longleftrightarrow\quad
 \ker I\subseteq\ker Q_{a,C}.
\]

必要性由同输入同输出得到；充分性是在每个 I-fiber 上赋其唯一 Q 标签。这只是信息可恢复性的基本事实。它不保证允许的原生表示、解码器、局部构造、计算效率或学习泛化。

因此需要分开回答：

1. 允许来源是否还含有所需区分？若没有，报告不可修复或执行显式补取。
2. 所需区分能否转成原生可执行表示？正确的类标签本身不是可运行的修复。
3. 修复和后续执行的总成本是否优于保留更多信息或完整重建？

既有“扩大契约后需要补回已忘 delta”的边界属于第一问。不能用重新编码的公式掩盖来源获取。

## 5. 上层表达三：需求是组件集合上的性质

当某个载体确实有原生解码器 D_S 和可执行保留子集 S 时，设

\[
 P_S(x)=D_S(E_S(x)).
\]

D_S 所需的共享状态、补取和重算都必须公开计费；若该载体没有这种解码接口，则直接比较原生执行轨迹，不能虚构 P_S。

对于当前组件全集 J，省略集合 K 的激活判据是

\[
 \mathsf{Act}_C(K;x)
 =\mathbf 1\{B_C(P_{J\setminus K}(x))\ne B_C(x)\}.
\]

这允许同时表达：当前观察无差异、经过后续动作却有差异；以及多个组件共同省略才有差异。它是供推导和验证使用的语义判据，计算完整 B_C 不能自动成为高效构造。

**不能把集合需求替换成单组件需求的并集。** 例如两个组件 u=v=1，观察为 u OR v，省略值按零解码。分别省略任一组件都安全，同时省略两者会出错。这个小例子仅用于反驳错误的一般推论，不是实验数据或新机制证据。

一条可贡献的路线是：在明确的算子/组件类中，由实际依赖或干预结构构造可检查的需求证书，使其在无需枚举整个未来行为表的情况下决定安全省略与修复区域。必须另证联合省略的正确性，或者报告保守程度；一般情形不预设唯一最小子集。

已有图实例说明这一接口怎样落地：

\[
 \mathsf{Need}_{G,A,h}(e\mid B\setminus\{e\})
 =\mathbf 1\!left\{
 \lambda_A^{G\cup(B\setminus\{e\})}(e)\le h
 \right\}.
\]

在既定 DAG、全可达性观察、仅 base edges 可失败的条件下，这个条件式 cut 判据形成可执行保留子集；已有审计说明消费原预算时无需复活遗漏组件。这个结论不外推到任意记忆、缓存或码本；cut 构造也不在这里升级为新图算法。

## 6. 上层表达四：维护程序及其优化目标

一个维护策略 Pi 在每次动作到来时，仅凭当时允许的信息选择程序：复用、局部修复或完整重建。程序可调用已声明的 `Drop/Acquire/Repair`。动作之后仍由固定原生解释器执行；参考行为由原始状态执行相同动作取得。

对于有可执行解码接口的精确实例，维护后的 z' 必须满足

\[
 \boxed{
 B_{C/a}(D(z'))=B_{C/a}(T_a x),
 \qquad z'=\mathsf M_a(E(x),W(x),m,C).
 }
\]

动作本身的输出和合法性也要匹配。M_a 表示维护与原生动作组成的实际程序；它不获得右侧的审计答案。这个行为等式比“两个编码标签相同”更直接地约束原生执行。

若存在一个指定的 canonical encoder，可再检查更强的编码交换式

\[
 \mathsf M_a(E_C(x),W(x),m,C)=E_{C/a}(T_a x).
\]

编码交换式需要独立的解码正确性，不能代替原生行为验证。其他表示族只须满足其声明的行为目标；不强迫精确分区或去掉所有多余信息。

统一优化对象是**允许接口上的维护程序**：

\[
 \boxed{
 \min_{\Pi\in\mathcal P_{\rm allowed}}
 \mathbb E_{\mu,\nu}\!\left[
 c_{\rm init}+\sum_t c(I_t,\Pi_t,a_t)
 \right]
 }
\]

约束是对声明的状态与动作契约执行时：

\[
 \widehat\tau^{\rm hard}_{\Pi}(x,\alpha)
 =\tau^{\rm hard}(x,\alpha),
 \qquad
 d(\widehat\tau^{\rm soft}_{\Pi},\tau^{\rm soft})\le\varepsilon,
 \qquad
 \max_t\operatorname{Storage}_t\le M.
\]

默认精确契约要求这些约束对声明域中所有 x、alpha 成立；若只要求分布性保证，必须另写概率与置信目标。mu、nu 分别是声明的状态、动作分布，用于期望成本，不能从评估结果事后选择。

`hard` 包含不能以任务准确率抵消的合法性、权限与版本语义；`soft` 的距离、容忍度和聚合方式按载体声明。对数值误差、检索召回和权限错误不使用一个未经解释的混合分数。随机执行需改用明确的轨迹分布目标或耦合，当前确定性式子不自动证明它。

成本至少含初始化、全体保留资源、元数据、来源获取、证书计算、探测、局部修复、完整重建与原生执行。时间、调用数与内存优先分别报告；若采用加权成本，权重提前固定。策略只读取当时可见输入；知道允许动作族不等于知道未来实际动作或评估标签。

## 7. 从规格到自己的方法

最小可实现的公共接口是：

`allowed view + arrived operation -> demand certificate -> feasible maintenance program -> native execution`

下一步先写每个具体载体的组件清单、算子读写集合、来源获取接口和成本表。然后提出实际可计算的 certificate 与 program constructor；若只有理想化的 Act_C 或完整答案枚举，就仍停在规格层。

贡献候选按以下顺序筛查：

1. **需求证书：** 能否利用组件交互结构精确或有界地识别操作需求？与普通依赖闭包、版本失效和已有专用判据比较。
2. **修复构造：** 能否只补取必要来源、只重算受影响区域，并给出联合修复的原生正确性？与完整重建和成熟增量维护比较。
3. **资源决策：** 能否在相同允许输入和总预算下获得更好的行为/成本权衡？与固定刷新、精确复用和已有多保真策略比较。

三个层次不必须全部创新。先确定一个无法由强基线便宜解决的障碍，再形成一项方法贡献。本文没有选定新算法，也没有证明某种统一策略跨载体有效。

## 8. 三个载体在同一规格中的位置

| 候选载体 | 组件与原生动作 | 被激活的需求 | 可检验的维护程序 |
|---|---|---|---|
| 编辑缓存 | 缓存块、生成条件；编辑向量扰动和连续编辑 | 双侧损失差所需的计算信息；精确因果不受影响区先排除 | 重算受影响块，必要时探测或校正；全调用成本计入 |
| 共享记忆 | 声明、来源与版本；纠正、撤销、并发提交 | 当前合法来源与仍有效推导的区分 | 提交校验、来源补取、局部重生成；权限作为 hard 约束 |
| 可编辑检索 | 码本绑定、版本与路由状态；新增、回收、重绑定 | 新旧引用的指代与检索语义 | 版本化、局部重编码或重新学习；码本和历史支持均计费 |

它们共享问题与接口，尚未共享一个已验证的方法。优先筛查一个主载体；第二个用于检验同一证书/构造规则能否迁移，第三个用于边界检查。每个载体若必须重写核心规则，就收窄论文范围。
