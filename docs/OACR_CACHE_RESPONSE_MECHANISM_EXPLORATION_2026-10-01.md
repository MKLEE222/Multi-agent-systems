# 固定前缀复用怎样使编辑损失对扰动失去响应

日期：2026-10-01。状态：已执行的组件机制开发检查；不是独立自然任务确认、完整 MobiEdit 复现或新方法验收。

## 这轮的判决

从缓存块、token 编辑注入和注意力传播出发，观察到一个具体行为：**锚点输出相同或接近的固定前缀缓存，在覆盖编辑 token 时，可以让后续 token 的损失对编辑扰动完全失去响应。把位点移出缓存，或恢复受影响位置的实时 K/V，响应恢复。**

这比泛称“旧缓存不准确”更具体；但它有简单的因果依赖解释，精确因果复用就能消除结构性问题。当前没有证据说明需要学习刷新才能保留这个响应，也没有测得精确复用之后仍存在不可接受的全成本。因此，A 的学习型刷新方法主张暂停，不进入 P1 方法比较。该结果保留为机制筛查及排除路径依赖的证据。

原先的“调用顺序可能造成偏差”在固定同一缓存锚点的检查中没有出现。完整训练器的 target/KL 初始化与刷新状态尚未执行，不能把这个局部零结果扩大为整个训练过程无顺序效应。

## 原生组件与可执行操作

加载官方仓库提交 `5a07b7906baa5457c15bd86cc012b1993ef6d3c6` 的原始 `server/mobiedit/easyeditor/models/rome/modeling_qwen2.py`，git blob 为 `defdad8cd04a5366016b5b6185b014af24d1784f`。通过 git 获取完整文件后哈希匹配，早先检索文本的字节缺失已解决。运行时是 Python 3.12、Torch 2.5.1+cpu、Transformers 4.44.2、NumPy 1.26.4；不等同于官方全部依赖环境。

| 对象 / 操作 | 实际实现 | 本轮控制 |
|---|---|---|
| 缓存组件 | eager 分支 ModifiedSelfAttention 保存各层前 p 个 token 的 Q/K/V | 每个对照重新清空缓存，在 delta=0 生成固定锚点；记录形状、字节数和指纹 |
| 编辑操作 | 第 ell 层、token j 的 MLP 输出加 delta | forward hook 注入；模型权重和输入固定 |
| 后续观察 | 最后一个输入位置的 logits 和指定标签损失 | 标签仅用于依赖测量，不是事实编辑正确答案 |
| 完整执行 | prefix=0，每次重新计算 Q/K/V | 原生代码仍可能保存空缓存，但不替换实时 Q/K/V |
| 固定前缀复用 | 所有层 prefix=p | 使用官方文件未修改的缓存分支，固定同一锚点 |
| 精确因果复用 | 至编辑层保留 p，后续层仅保留 min(p,j) | attention pre-hook 设置边界；逐层只复用不受注入影响的位置 |

模型文件没有重写。精确因果边界是对照干预，不宣称为新的缓存算法。官方缓存只节省部分 Q/K/V 投影；本轮不能把它当成跳过整个前缀网络的执行。

## 从算子推出的预测

设序列长 n，编辑位置 j<p<n，目标位置 n-1；注意力因果、其余子层逐 token、权重固定、无 dropout，且各后续层的缓存都由同一锚点生成并保持冻结。

注入之后，编辑 token 影响其他位置的路径须经过后续注意力的 K/V。若这些层把整个前缀 K/V 替换为锚点值，后缀看到的前缀 K/V 不再随 delta 改变。对后缀逐层归纳，其状态、最终 logits 和仅依赖该位置的损失都与 delta 无关。因此在这些假设下，

\[
 L_C(\delta)=L_C(0),\qquad
 D_C(u,\varepsilon)
 =\frac{L_C(\varepsilon u)-L_C(-\varepsilon u)}{2\varepsilon}=0.
\]

完整执行的响应可以非零，但并非每个方向都必然非零。这里测量有限差分，不把它自动当成精确梯度。

由相同依赖结构得到三个消失条件：

1. j>=p 时，复用位置严格位于编辑之前，不受 token 注入影响。
2. 编辑位于最后一层、且不是目标位置时，注入之后没有跨 token 传播层，fresh 和 cache 都应无后缀响应。
3. 仅复用不受影响位置时，真实依赖路径恢复。零起始层号下，边界是

\[
 p_k=\begin{cases}
 p,&k\leq\ell,\\
 \min(p,j),&k>\ell.
 \end{cases}
\]

编辑发生在本层注意力之后，所以本层仍可保留 p；后续层只能保留严格早于 j 的位置。此处假设各 batch 行位置相同；真实行位置不同时需另行处理。

这是标准因果依赖与计算图归纳，不是新的通用定理。它把上层“对后续操作的充分性”落实为当前组件究竟保留了哪些干预影响路径；没有验证共享记忆或码本也遵循同一个机制。

## 已执行证据与完整分母

协议与脚本在各自开发检查执行前保存。预训练协议在小模型结果之后制定；数值分块对照在预训练结果之后制定。后两者分别是机制扩展和事后数值诊断，均不冒充独立确认。

### 原生小模型：96 个机制配置

两个随机初始化、三层 Qwen2 架构；2 行、16 token；p=10；编辑层 0/1/2，位置 2/9/10/12，四个固定方向，epsilon=0.001。三种执行均有同锚点正向及反向配对。以下分组互斥，合计 96，不把行或种子当成自然任务数量。

| 预先声明的条件 | 配置数 | fresh 响应 | 固定缓存响应 | 精确因果复用 |
|---|---:|---|---|---|
| 编辑在缓存内、非最后层 | 32 | 32/32 有非零损失差分 | 32/32 差分为零 | center/minus/plus logits 与 fresh 逐值相同 |
| 编辑在缓存外、非最后层 | 32 | 32/32 有非零损失差分 | 与 fresh 逐值相同 | 与 fresh 逐值相同 |
| 最后一层注入 | 32 | 32/32 差分为零 | 同样为零 | 与 fresh 逐值相同 |

96/96 锚点 logits 的 fresh/cache 指纹一致。缓存内早层条件的最大 logits 误差为 0.00101405，最大有限差分误差为 0.0847028。精确因果复用在全部 96 个配置、三侧比较中最大 logits 误差为 0。288 个执行变体的缓存锚点保持不变，反向配对最大误差为 0。

原始报告的 outside 分组包含最后层的 16 个配置，和 last_layer 分组重叠；上表重新按互斥条件汇总。原始报告原样保存。

### 预训练模型：12 个手工机制探针

Qwen/Qwen2.5-0.5B，固定 revision `060db6499f32faf8b98477b0a26969ef7d8b9987`；24 层、float32、eager、CPU。两句关于 Paris 的手工提示来自同一底层事实，编辑位置分别为 0 和 21；p=10；层 0/5/23；两个方向；epsilon=0.01。诊断标签是字符串 “ London” 的第一个 token，不作为事实正确标签。

| 条件 | 探针数 | 结果 |
|---|---:|---|
| 编辑在缓存内，层 0/5 | 4 | fresh 差分均非零，固定缓存差分全部为零；fresh 差分绝对值范围 0.000995843–0.0902184 |
| 编辑在缓存外，层 0/5 | 4 | 固定缓存与 fresh 均保留非零响应；存在浮点分块差异 |
| 最后一层，两个提示 | 4 | fresh/cache 差分全部为零 |

固定缓存在锚点与 fresh 的最大 logits 差为 2.09808e-5；因此预训练结果仅支持锚点近似一致。精确因果复用与整体 fresh 的最大 logits 差为 2.67029e-5，最大差分误差为 0.000462987，不能直接按事后选择的阈值宣布“精确通过”。

随后对同样 12 个探针，令每次 fresh 都重新计算全部 Q/K/V，但按精确因果复用的矩阵形状拆成两块。三侧 logits 与精确因果复用在 12/12 探针中逐值相同，差分也逐值相同。**本次偏差可由 fresh 的矩阵分块计算完整复现，无需旧缓存内容。** 这个结果只排除了已执行条件中的结构性偏差，不保证其他精度、内核或 epsilon 下的数值误差可忽略。

### 接口异常与尚未覆盖的集成

单独调用官方文件时，prefix=0 冷启动再 prefix=10 触发 IndexError；传 update_prefix=True 触发 LM.forward 的 TypeError；sdpa 分支收到 prefix 触发 TypeError。这些是固定源文件和所用环境下的接口结果，保留完整异常，不当成科学现象或方法贡献。

所读编辑入口使用 AutoModelForCausalLM；本轮没有建立默认完整编辑管线如何载入这份自定义模型文件。也没有执行量化器、官方训练器、KL 初始化、连续优化、事实编辑评估或手机硬件。因此不能据此宣布 MobiEdit 论文结果错误，不能声称完整训练默认路径必然出现本现象。

## 下一项应解决的不确定性

继续 A 时，先回答：**在允许操作真正改变缓存依赖的场景里，标准失效与精确重算之后，是否还存在可重复、实际的资源障碍？** 需要先核对真实执行入口，明确权重/输入/位置/掩码/锚点的读写集合，比较完整计算、标准依赖失效和精确复用的全成本。不能仅换成更多模型重复这次固定前缀反例。

只有强简单基线无法在预算内保留所需操作响应，才进入“有限预算如何选择受影响组件及重建时机”。精度切换有历史成本是邻居明确未建模的限制，尚未证明是我们的空白，也没有据此构造新算法。
