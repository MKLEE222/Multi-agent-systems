## 2. 本轮只执行经典文件绑定参考

文件：`experiments/oacr_native/file_binding_v1.py`、`audit_file_binding_v1.py`、`file_binding_v1.json`。

它是一个回执驱动的经典参考，不是 OCAR 新算法，不是已经优化的完整强基线。producer 只接收调用、参数和回执；不接收初始化场景、原生 backend、私有字段、任务评分或未来轨迹。初始状态由 native evaluator 设置，producer 用公开 pwd 建立初始位置。

事实以公开位置/名称绑定保存；不存在全局 inode。已读内容在已确认文件的成功 mv 后重绑定，cd 改变当前定位上下文，echo/touch 等回执更新已知值；未知值不从 ls 猜出。未支持的成功目录移动明确返回 UNSUPPORTED，不能当 EXACT。

范围：初始位于根；单层导航、有限 ASCII 名称、移动前已确认源类型为文件；正向检查假定没有未观察写入。错误分支只对已审查的操作使用。一般异常、其他操作与目录移动不在此原型承诺内。KNOWN 是该参考的知识输出标签，不是新证书系统或全称正确性定理。

## 3. 冻结的最小执行与独立检查

使用固定 BFCL interpreter `6ea57973c7a6097fd7c5915698c54c17c5b1b6c8`，原始两个模块必须通过 SHA256 校验，不修改 native 代码。`source-root` 指向含 `bfcl_eval` 的目录；依赖从同一修订取得。临时 native 源码不加入本项目，正式复现从固定上游修订取得。

7 个预设 fixture 覆盖：连续重命名、移入目录、同名文件的不同目录、失败移动、重绑定后改写、隐藏名称/过滤 ls、明确不支持的目录移动。它们用真实解释器，仍是人工构造的接口审计，不是 BFCL 官方任务或独立自然机制证据。

每个回执更新后，对预设名字请求参考输出。KNOWN 与复制的 native backend 实际 cat 比较；这些 verifier-only 调用不回流给 producer，并单独计数。NEED_EVIDENCE 与 UNSUPPORTED 保留全部分母，不按成功处理。完整 ledger、代码/配置/source 哈希和每个表示字节数保存，不从字节数推断完整任务成本优势。

两项预设边界见证：未知源文件/目录可以给出相同可见 prefix 和 mv 回执，但后续 cat 不同；未观察 writer 可使相同观察历史的后续 cat 不同。前者说明需来源/类型依据；后者说明 monitored-writer 条件不能悄悄扩大。它们是经典信息/观察边界，不当新定理。
