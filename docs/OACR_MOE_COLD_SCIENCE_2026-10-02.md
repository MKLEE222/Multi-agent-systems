## 1. 冷判断

**研究确实卡住了，但现有负结果同时混有三个不同对象：候选没有测得独有优势；载体不能测量某些想要的收益；升级协议把不同论文身份捆成一个终点。不能把三者都归结为“原创不够”。**

没有证据支持把当前需求回推方法升格为新内核。也没有证据支持“因此 OACR 只能不断换载体直到三层均原创”。合适的下一步是先把可主张的增量与可测量的机会分母对齐，再决定是否构造方法。这项诊断可以和原系统复现并行，不应变成研究的新串行 gate。

### 已有证据的精确含义

| 事实 | 支持的结论 | 尚不支持的结论 |
|---|---|---|
| 图内需求、证书及维护在已测语义/成本上被经典控制匹配（G） | 这些实现的已测优势不能作为独有算法贡献 | 一切预算维护问题都被经典理论解决；所有新结构都不可能有结果 |
| BFCL 50 个公开开发案例，73 次实际 read；候选和经典各正确预测 19，各需取证 54（E） | 当前适配正确；该样本内覆盖没有增量 | 两个算法在所有合法历史上等价；54 次均信息论不可解 |
| 原回执规则下省调用各 0；50/50 轨迹通过（E） | 本轮没有原官方调用节省；参考轨迹执行接口可靠 | 方法无法避免物理读；闭环 agent 已完成 50 个任务 |
| 当前候选查询访问 169 对 84，更新访问 466 对 939，bundle 峰值和多 5,000 bytes（E） | 有方向相反的已测程序访问成本和额外存储 | 完整成本相同；候选总体更快；可以把两种访问直接相加比较 |
| BM25 选定 witness 覆盖 17/19，full-prefix 覆盖全部，原始 prefix 短（E） | 在当前输入规模上，简单回查已很强 | AMA 完整系统无效；未覆盖该 witness 等于答案错误 |
| 完整 AMA/ACE/AgeMem 模型系统未运行（E、B） | 端到端比较仍未完成 | 这些方法一定有原生状态失败；它们一定消除本研究问题 |

一个容易混淆的细节：原官方检查器要求参考回执在累计实际回执中出现，首次从旧依据推导的新形式回执不能据此计入省调用（E）。这不是原检查器“错误”，而是它评价的是规定的执行/回执契约。它和“中间件能否计算出正确工具回答、免去一次外部执行”是不同目标。两个目标可以同时报告，不能用诊断性替代规则冒充官方得分，也不能把官方 0 当成所有语义复用收益的反证。

## 2. 哪些是真研究问题，哪些来自协议或任务

| 卡点 | 分类与依据 | 应采取的处置 |
|---|---|---|
| 当前构造被正确经典维护追平 | **真实负证据。** E 的覆盖逐 read 完全相同；G 的图控制也匹配已测保证/资源。不能用更漂亮的证据列表复活算法贡献 | 停止推广这些已测差异为新内核；保留可靠适配和对照资产。另一个输入族上的分离须重新证明，不能由本轮相同或不同外推 |
| 未观察的初始内容、不可见外部写入 | **可能是真信息边界，尚需见证。** G/R1 已要求合法 repair view 决定目标类；E 没有把私有初态喂给 producer | 对指定当前 read，构造同可见前缀而不同回执的两个原生相容状态，才能确认该接口的信息歧义。不要拿“unknown”输出作证明 |
| 未知类型、目录 transfer、导航命名空间触发保守失效 | **当前实现/规格范围，未定性为信息边界。** E 有 14 个案例进入此模式；不能据案例数推出受影响 read 数 | 用更强而收费一致的 heap/alias 控制检查能否补齐。补齐成功归入适配基础；补不齐仍不自动证明所有方法不可解 |
| 原官方回执规则下首次派生读不能省 | **测量目标限制。** 它在方法竞争前就缩小了可省分母 | 报告“可正确派生”“具原回执资格”“真正省外部执行”三个分母。若主贡献是避免外部读，就另列清楚的物理调用估计量，官方结果照报 |
| 动作由 reference 逐次供给 | **决策对象缺失。** 没有 actor 的缺口识别、后续动作改变或成功率增量（E） | 回放可研究执行模块，不能承担学习 agent 主张。不要把 replay 做得更复杂后改名为闭环比较 |
| 历史短、BM25/full-history 接近覆盖所有 | **载体缺乏区分强度的推断。** 这是由 E 的输入规模与 accessor 结果推得，未证明所有 BFCL 子集都短 | 若想研究长程记忆，应先在原强方法任务中查合法依据跨度、干扰、支持改变与成本分布，而非在当前短轨迹中手工拉长历史制造“自然优势” |
| 把经典控制逐次扩成能够吸收任何新组件的组合 | **对照边界风险，不是现有匹配结果的无效理由。** B 明确这是我们构造的控制，不是一篇已复现论文 | 每轮冻结一个可实现的控制、其合法输入和优化预算。允许对照改进，但记录版本。竞争对象应是具体实现/结构族，不能是“所有正确经典方法”，后者当然可把候选重新命名后收入自身 |
| 原模型角色/checkpoint/runner 和计算接口未齐 | **实验工程/可用性问题。** 不构成新颖性的正负证据（B、E） | 独立做版本胶囊与最小 native sanity。不得把未跑系统换成 accessor，也不能因当时“未见 runner”就断言不存在；须包含子模块/依赖入口的源码核对 |

相同合法观察不能唯一决定当前回执时，任何只用这些观察的确定性程序都无法同时对两种状态输出各自正确答案。这是现有 G/R1 的信息约束，不是本报告的新理论。反过来，某个实现拒绝输出，甚至某个更强控制也拒绝输出，都不足以证明这个约束成立。

## 3. 验收哪里过强，哪里必须保留

### 3.1 旧升级身份可以严格；不能把它当所有科学贡献的唯一入口

G 要求 `UPGRADE PASS` 同时满足 T/I/N 和 R1–R5；而且已有 `SCIENTIFIC PASS / UPGRADE INCOMPLETE` 这个限定结论。对一个事先承诺了通用修复理论、双向可执行维护、learned carrier 和自然规模证据的完整升级，这样的验收可以成立。问题是把它进一步解释成：**任何值得继续的候选都必须同时完成这整组义务，并让现象、理论、方法各自独立首创。** 这是项目身份与候选筛选的目标错位。

P 的“尽量让……每层各有独立首创”、G 的“The user's aim remains independently novel phenomenon, theory and method”已不反映最新用户目标。应在唯一 gate 中统一纠正，不能只在聊天里暂时豁免。也不必追溯降低旧升级的冻结标准；新的具体主张应注明需要哪些门槛，而不是借“用户降低期待”给未成立结果盖章。

### 3.2 按主张绑定义务

| 拟主张 | 必须有的证据 | 不应自动附加的义务 |
|---|---|---|
| 一个具体原生操作下的新实证规律/失败机制 | 不采用新方法也能测量；合法干预、反例与消失条件；最近现象/机制近邻审查；独立确认或适当聚类的不确定性报告 | 必须再给一项独立新算法、精确 quotient 理论和多个模型族 |
| 重用成熟工具但具有新保证、结构范围或成本界的方法 | 明确继承部分；额外结果与近邻定理对齐；公平强控制；对应可执行验证 | 所有零件都是新发明；现象也首次被人观察；理论必须同时覆盖所有硬度、双向性和唯一性问题 |
| 已知机制指导的新原生适配/完整系统发现 | 原系统对照；模块归因；合法角色输入；完整成本及实际收益；明确价值在哪一层 | 以组合命名充当新内核；或者仅因用了经典部件就预先判为无科学价值 |
| 精确行为商/可维护充分表示 | G 的信息可用性、encoder/decoder/updater 及声明合同内正确性要求 | 用任务准确率改善顶替这些要求 |
| 跨系统同内核规律 | 同一个预测/构造规则、原生接口、相应自然证据与边界 | 把几项互不相关审计按数量相加 |

T2 的新理论要求不能退化成常识恒等式，但若主贡献本身是经过确认的机制/系统结果，新理论不是自动必需。T4 双向 repair 只对相应主张生效；不应强迫一项单向安全复用方法去证明已毁信息可恢复。N3 的“hundreds”、N4 的 learned repair 对其原升级主张有效，却不应排除一项证明清晰的原生符号方法。自然发生率的样本规模仍须由统计单位、聚类和目标精度决定，不能凭 50 个案例或 millions of replay 自动达标。

### 3.3 没有理由放松的部分

保留合法信息与评分契约、producer/verifier 分离、冻结与暴露状态标签、不删失败和困难任务、原始历史/缓存及经典强能力的公平保留、构建/更新/检索/模型的完整收费、原生独立执行、未知与规格不支持的区分、相应主张的近邻审查。512 封存保持。这些是识别和可信度要求，不是三层原创的代用品，也不是困境的主要制造者。

当前 gate 没有规定必须涨几十个百分点。无需为此新增或删除数字门槛。小收益是否值得发表，取决于测量误差、代价、任务意义以及它支持的独立主张；0 个官方省调用和无独有覆盖仍然不能靠“允许小收益”解释成正结果。

## 4. 今天可执行的解困动作：一次分母与原因审计

**候选动作 A：对已暴露的 73 个 read 做“可计算性—原回执资格—失败原因”同步入口审计。** 它的产物是去留决策表，不是一个新算法，也不是必须做完才允许其他研究的 gate。只需现有公开 native runner、原固定轨迹与结果，不需要模型接口。

执行规格：

1. **先固定问题。** 本轮只估计“指定已提出 read 的回执能否由过去角色可见记录精确计算，以及是否具备原官方省调用资格”。动作仍来自 reference。冻结所有 50 cases/73 read IDs，不按机会筛子集；当前已暴露的数据全部标开发诊断。
2. **给所有行增加两组相互独立的字段。** 知识状态为 `known_exact` / `native_ambiguity_witness` / `implementation_or_scope_gap` / `unresolved`；回执资格为 `eligible_under_original_rule` / `not_eligible` / `unresolved`。另记录已实际取得同序列化回执的次数、该分支所需出现次数、候选和经典状态、unsupported effect/type/namespace、最近可见内容来源。不要把 `not_eligible` 当 `unknown`。
3. **19 个 known 行做评分归因。** 对照原生回执与旧官方判据，逐行公开到底是回执尚未实际取得、出现次数不足，还是其他条件禁止省。原检查器继续原样运行；语义派生可行性另列，绝不把虚拟回执记成已经执行的原生调用。这一步能把“有正确计算却零省调用”的原因变成可核对的账，而非口头解释。
4. **54 个 unknown 行做证据与范围归因。** 先按可见写入/读回执、copy/move、类型/导航失效分桶；再用固定的、收费一致的更强经典语义控制尝试补齐。对无法补齐者，只有找到两个 native 合法状态，完整已见前缀的所有可见回执均相同、当前 read 回执不同，才记 `native_ambiguity_witness`。只改 hidden state 后看当前输出不同不够；必须重新执行整个已见前缀。没有见证、仅未完成检查者保留 `unresolved`。
5. **限制事实权限。** 私有初态、未来动作和回执只在 verifier；歧义见证是开发期回顾性诊断，不向在线 producer 提供 oracle 信息。进一步的机制假设若由这些结果提出，下一次确认必须另行前瞻冻结，不能把本审计当独立确认。
6. **交付一张全分母表和一次决策。** 行覆盖完整 73；官方原规则成绩照报；本地正确派生数照报；不以“unknown 都很难”叙事填补空值。该审计直接回答此载体有没有可研究的合法机会，以及差异出在算法、接口还是估计量。

预先约定的决策，不需要巨额收益：

- 若 54 行主要有可验证的真实观察歧义，研究对象应转为合法取证/来源获得的策略或界限；不能继续把缓存结构当能创造缺失内容。是否有新结果仍要和已知 sensing/信息状态方法比较。
- 若更多行由更强经典控制补齐，当前 gap 是适配债务；不要包装为新机制。适配可以成为系统部件，主论文应另找可检验增量。
- 若差异主要出在原回执资格，而语义复用始终两者一样，则 BFCL 本轮只作正确性载体。停止用这个分母来追求独有省调用；也不改原官方分数来造胜出。
- 若产生一个真实、可重复且经典控制未覆盖的结构困难，只把它登记为**待检验候选**。先说明相容世界、原生效应与最小补取问题，再选方法；不能从一行困难跳到新内核结论。

这次审计的必要性是“避免把不同障碍继续混作一个负结果”。若 root 的另一路源码/原系统调查已经提供这些逐行原因，它可以直接复用；不要再跑一遍只增加体量。

## 5. 两条备选路线

### 备选 B：有限、固定模块的成本交叉实验

适用条件：存在足够语义复用机会，目标是部署成本，且不依赖原官方回执得分证明价值。

直接比较已存在的 `IndexedViews` 与 `DemandViews`，覆盖保持同等。固定保留 raw history、语义片段、实例输入及读写比例；优先使用公开轨迹真实前缀，不把人工加长轨迹称为自然分布。重复测构建、更新、查询 CPU/时间和实际 bundle/RSS，保持工具执行成本单列。已有 939→466 更新访问和 84→169 查询访问只是定位交叉点的线索，两类访问不能直接相加。经典对照允许合理 lazy/demand 版本及同等优化预算。

今天即可冻结测量程序、执行小范围重复性能检查；它不需要 actor 或新凭证。若只得到短轨迹上的微小噪声差异，停止性能主张。若存在可靠交叉区间，再问这个区间是否在实际任务中出现、优势是否来自新的保证/构造，或只是已知 eager/lazy 权衡。后者仍可指导系统，但不冒充新理论。

### 备选 C：回到一个完整强方法的原任务，先查机会而非先移植内核

适用条件：BFCL 的短前缀/回执契约使想要的记忆收益不可识别，或者目标是闭环 agent，而非指定 read 模块。

从 B/E 已指定的 AMA 原生 TextWorld/Spider2 或 ACE 的原任务入口中**只选一个能够核实运行链的对象**。今天做源码和数据的可行性清单：固定 paper/code/submodule SHA；确认 native runner 和角色可见数据；登记外部模型/checkpoint需求；检查公开轨迹中“过去依据到当前决策”的跨度、无关上下文比例、支持被实际操作改变的次数，以及 full-history 回查的实际成本。检查子模块是必要步骤；B 的“此树未见 AppWorld runner”只是当时的审查状态，不是 runner 不存在的证明。

这里可用公开开发轨迹作 census；若作者数据 test-only，因本轮检查已经暴露，应明确改称开发，不再作未见测试。缺接口时交付可核对的版本胶囊与缺项，不能用 reference 动作、stub actor 或 accessor 分数填补完整系统。已有被授权模型可用时再开展同 actor 的原方法/加经典/加候选比较；没有时不新建凭证、不调用付费模型。

转入该任务的理由须是原任务里确有合法、可计费的长跨度依据与支持变化；不是某篇论文得分高，也不是想找对手失败。若 census 显示 full-prefix 本已足够且维护几乎无作用，同样可以退出。完整基线运行有助于定位增量，但不是所有符号结果或新现象研究都必须先完成的普遍前置条件。

## 6. 建议 root 采用的结论

1. 当前图与 BFCL 的回推/维护候选不升格为独有内核；这是已有负证据的正常结论，不等于整条研究线失效。
2. 在唯一 gate 中纠正“三层各自原创”的强制解读，并使 T/N 子义务随具体主张生效；保留所有识别、公平性、原生评分和封存规则。
3. 今天并行完成入口原因审计和一个原系统可行性核对。它们给出“什么值得解释、什么只是补适配”的依据；不预先指定新算子，不要求巨大百分点收益，不把更多审计数量当科学突破。

本报告没有确立新的机制、理论、算法或自然发生率。它提出的是缩短错误研究循环的可执行科学决策：把“对手追平”“可见信息不足”“实现不支持”“评分不接纳”“任务没有足够记忆负荷”分别处理，然后只对仍存在的独立主张投入构造与确认。
